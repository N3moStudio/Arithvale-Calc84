# Arithen media tester brief for Codex

Use a disposable iPhone simulator and synthetic media. Record the app commit, device, OS, available bytes, and fixture hashes. Use the normal app UI for actions described as taps. Label separate PhotoKit, vault-engine, and host measurements by their actual layer. Keep generated recovery keys and private photos out of reports.

1. Launch from a clean install. Check calculator input, then type 160160 and hold Equals. Complete the normal recovery confirmation and choose a disposable access code. Relaunch and unlock. Verify a wrong entry leaves the calculator usable.
2. In Add to Library → Photos & Videos, cancel once, immediately retry, select a recognizable seeded image, grant the requested permission, and keep originals. Confirm the committed count and visibility after locking and reopening. Exercise limited and denied Photos permissions on independent clean devices where available.
3. Seed a screenshot and two distinguishable movies with capture dates exactly one week earlier. Record each original’s filename, date and time including offset, byte count, and digest. Import and use Save to Photos. Identify the newly created Photos asset by its new identifier. Compare its original resource bytes, creation date, and movie duration. In Photos, check that sorting by Date Captured places the export alongside last week’s neighbor assets. Switch to Recently Added and check that the newly saved copy appears among recent additions. Keep these two observations separate.
4. Test a full 150-screenshot selection, a mixed selection that includes 30-minute 3840×2160 movies at 30 and 60 fps, and the picker limit. Repeat imports. Measure from submission to visible progress and separately to the final import receipt. Record successful counts, failures, byte totals, elapsed time and whether every item survives reopening. Only call an import complete after bytes are durably stored and verified. Test cancel, retry and original retention.
5. Grow a disposable vault in measured steps. Use streamed inputs above the old 4 GiB file limit. Check an oversized sparse input is rejected without changing the library. At each successful step, export, compare all bytes and reopen. Stop before the next step could exhaust runner storage. Report the largest measured file and aggregate separately from the configured ceilings. Distinguish synthetic low-bitrate movie playback from storage-throughput tests.
6. On physical iPhone, repeat with locally captured Cinematic/HEVC/HDR footage, an iCloud-only original, normal screenshots, and restricted free space. Check playback, original timestamps, focus edits when present, heat, memory termination, lock/background interruption, and recovery. Record format and actual bytes. Label missing hardware or credentials explicitly.

Report pass, fail, skipped or untested for each scenario. Attach a redacted screenshot at each decisive UI step and quantitative evidence for performance claims. Compare the measured time for 150 screenshots with the one-second target. Do not infer a universal safe capacity from one benchmark.
