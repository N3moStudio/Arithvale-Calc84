## Implemented changes

| Before | After | Why |
| --- | --- | --- |
| Selection title had a one-line limit and could shrink to 75%, including accessibility text sizes. | Accessibility text gets a separate wrapping title row; quick lock and Cancel remain in the control row. Ordinary sizes retain the compact heading. | Makes the full selection count readable without competing with the controls. |
| Large filter labels shared a fixed-width row; bottom labels had no explicit centered wrapping policy. | Accessibility filters can scroll horizontally, with complete labels; dock/action labels wrap centrally and the dock gets more horizontal room. | Keeps actions available at larger text sizes without shrinking them. |
| `1 Snaps`, `1 items`, and `1 files received`. | Singular/plural labels and locale-formatted counts in the library, albums, completion card, and received-file screen. | Counts read naturally and large values are easier to scan. |
| A plain “Files received” button appeared for pending, working, and failed receipts alike. | A themed row distinguishes processing, ready, and needs-attention states, with progress/error cues and a route to the existing import screen. | The UI stops claiming a transfer succeeded when it is still working or needs attention. |
| Viewer controls scaled on press even when Reduce Motion was enabled. | Press feedback still changes opacity; the existing scale feedback only runs when Reduce Motion is off. | Keeps responsive controls while honoring the user's motion preference. |

Only five UI files changed: `LibraryView`, `SharedFilesImportView` (its view labels only), `PhotoImportReview`, `AlbumLibraryView`, and `MediaBrowser` (button style only). No persistence, cryptography, importer model, theme palette, calculator engine, or navigation ownership was changed.
